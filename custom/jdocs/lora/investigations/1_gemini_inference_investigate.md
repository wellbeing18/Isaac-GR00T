# Investigation Report: Poor Inference Performance (GR00T LoRA)

**Date**: December 13, 2025
**Subject**: Investigation of poor robot movement during inference despite low evaluation MAE.

## 1. Executive Summary

The investigation identifies a **critical data alignment issue** as the root cause of the poor inference performance. The dataset used for training (`datasets_groot`) was not correctly converted to the GR00T format. Specifically, the video files were not split into per-episode files, causing the dataloader to fetch incorrect visual observations (likely frames from Episode 0) for all training episodes.

As a result, the model learned to ignore visual input (which was uncorrelated with the actions) and rely solely on proprioceptive state priors. This explains why it "evaluates" well on state metrics (overfitting to state-action mean) but fails to perform the task visually during inference.

## 2. Root Cause Analysis

### 2.1. The Issue
The GR00T training pipeline (`LeRobotSingleDataset` / `LeRobotMixtureDataset`) expects a specific directory structure where each episode has its own corresponding video file (e.g., `episode_000001.mp4`).

The current dataset uses the raw LeRobot v3 "consolidated" format (`file-000.mp4`), where multiple episodes are concatenated into a single video file. The GR00T dataloader does not support seeking within these consolidated files correctly when using the `torchvision_av` or `decord` backends with the current configuration.

### 2.2. Evidence

#### A. Metadata Misconfiguration (`info.json`)
The `info.json` file in `/home/jrobot/project/XLeRobot/datasets_groot/meta/info.json` defines the video path pattern as:
```json
"video_path": "videos/{video_key}/chunk-{episode_chunk:03d}/file-000.mp4"
```
This points to the raw chunk file. The correct GR00T pattern (as generated by `convert_lerobot_v3_to_groot.py` when successful) is:
```json
"video_path": "videos/{video_key}/chunk-{episode_chunk:03d}/episode_{episode_index:06d}.mp4"
```

#### B. Missing Per-Episode Video Files
Inspection of the dataset directory reveals that no per-episode video files exist:
```
/home/jrobot/project/XLeRobot/datasets_groot/videos/observation.images.head/chunk-000/
  └── file-000.mp4  (Consolidated video)
```
There are no `episode_000000.mp4`, `episode_000001.mp4`, etc.

#### C. Diagnosis Script Failure
The `diagnose_groot_inference.py` script failed to load samples because it explicitly looks for `episode_*.mp4` files, which validates that the standard GR00T tools expect this format.

#### D. Model Behavior Test
A manual inference test showed:
1.  **State Responsiveness**: The model changes its output when the input state changes (Delta ~2-5°), indicating the weights are not "broken" or zeroed.
2.  **Blind Behavior**: When placed at a "Home" position far from the training mean, the model predicted a massive jump (+120°) to return to the center of the workspace. This suggests it is acting as a "mean restorer" based on proprioception, ignoring the fact that the camera sees a specific scene.

## 3. The Mechanism of Failure

1.  **Training Time**: When the dataloader requests "Episode N", it loads the State/Action for Episode N correctly (from split parquet files).
2.  **Visual Mismatch**: It loads the video from `file-000.mp4`. Since the offset logic for consolidated files is missing/incorrect in this dataloader configuration, it likely loads frames from the *beginning* of the video file (Episode 0) for *every* episode.
3.  **Learning Dynamics**: The model sees "Visual(Episode 0)" paired with "Action(Episode N)". Since the visual input is constant or uncorrelated with the action, the model learns to set the visual encoder weights to near-zero (ignoring vision) and minimizes loss by overfitting to the proprioceptive state -> action mapping.
4.  **Result**: A "blind" robot that moves somewhat smoothly (due to state interpolation) but does not react to objects or the environment.

## 4. Remediation Plan

To fix this, we must complete the dataset conversion process that was skipped or failed.

### Step 1: Re-run Dataset Conversion
We need to run `convert_lerobot_v3_to_groot.py` on the **original source dataset** (or the combined one if possible) to explicitly split the videos.

**Command**:
```bash
python custom/scripts/convert_lerobot_v3_to_groot.py \
    --dataset-path /home/jrobot/project/XLeRobot/datasets_groot \
    --robot-type so101 \
    --dual-camera
```

*Note: If the `combine_groot_datasets.py` script was used on unconverted datasets, it might be safer to delete `datasets_groot`, convert the source `pick_and_place` dataset first, and then re-combine.*

### Step 2: Verify Structure
Ensure the `videos` directory contains individual files:
```
videos/observation.images.head/chunk-000/episode_000000.mp4
videos/observation.images.head/chunk-000/episode_000001.mp4
...
```

### Step 3: Re-Train
The current model checkpoint (`.../groot_mvp_lora_20251212_180908058`) is invalid and must be discarded. A new training run (`train_groot_mvp.sh`) is required using the fixed dataset.

## 5. Conclusion
The "bad performance" is not due to hyperparameter tuning, LoRA rank, or inference latency. It is a fundamental data quality issue where the model was trained on mismatched video-action pairs. Fixing the dataset structure will resolve the blindness of the policy.
